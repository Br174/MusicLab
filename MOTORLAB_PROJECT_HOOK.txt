PURPOSE
Persistent MusicLab-side MotorLab hook. r14 keeps technical history separate from Bruno's visible Registro Modifiche e Ripristini and enforces a hard plan-before-write gate for every new application/project modification.

MANDATORY RULES
1. First user-visible project line: "⚙️ MotorLab attivo".
2. Reconcile MOTORLAB_PROJECT_STATE_MUSICLAB_V1.txt against newer live repository/job/artifact evidence before choosing the current starting point.
3. Preserve MusicLab native playback/search/AI/runtime engines and lifecycle identity.
4. Before EVERY NEW MusicLab write-capable modification, initial wording such as modifica/correggi/aggiungi/togli/ripristina is intent only. Perform read-only preparation, show Bruno the concise pre-change report, then wait for his approval of that report before source/config/lifecycle writes.
5. Approval continuity applies only within the described scope. Material expansion requires an amended report and new approval before broadened writes.
6. Apply Change Compatibility Guard, single-writer, Root Cause Closure and lifecycle protections.
7. Technical change history may keep verified/superseded/backfilled records and exact Git provenance; it is not the visible confirmed restore list.
8. The visible Registro Modifiche e Ripristini contains only specific modifications Bruno confirms as working and wants conserved.
9. Use plain stable numbers 1,2,3... One feature family keeps one number; a newer confirmed working implementation updates the same slot.
10. A multi-change LAB/APK never auto-registers as a whole. Save only the exact item(s) Bruno identifies for conservation. If his description is ambiguous, confirm the intended subchange before saving.
11. Failed/unconfirmed/experimental attempts never enter the visible register. Existing pre-r14 technical records are not promoted automatically.
12. After an actual persisted save/update, explicitly tell Bruno the register number.
13. "Ripristina N" resolves N read-only, presents the restore plan, waits for Bruno approval, then uses selective isolated-LAB restore unless whole-version rollback was explicitly requested.
14. Restore attempts do not advance the visible slot until Bruno confirms the result works and wants it conserved.
15. Eligible isolated LAB loops use risk-scaled Fast Iteration/No-Spin; HIGH risk and CANDIDATA/MADRE retain full gates.
16. Synchronize newer MotorLab releases only at safe boundaries, preserving LAST_GOOD. Metadata-only sync must not intentionally alter application runtime.
