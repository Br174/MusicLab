This file is the persistent project-side structural hook for MotorLab.

MANDATORY RULES
1. Do not require Bruno to paste an activation string in each new MusicLab chat.
2. At the first available user-facing response of every recognized MusicLab chat/session, visibly state that MotorLab is active and that it is operating alongside MusicLab's native engine. The preferred form is: "⚙️ MotorLab attivo — questa chat verrà elaborata con MotorLab, affiancando il motore nativo di MusicLab senza sostituirlo."
3. If the visible MotorLab startup message has not appeared, Bruno must not be expected to assume that MotorLab is active.
4. After startup, apply the current MotorLab progress percentage, watchdog lightning/recovery and verified fireworks-success contracts whenever applicable.
5. Br174/Chatgpt is the authoritative MotorLab control repository; do not embed or freeze a copy of the CORE here.
6. MotorLab must operate alongside MusicLab's native playback/search/AI/runtime engines and must never replace, disable, absorb, rename or rewrite them merely because MotorLab is active.
7. Before write-capable/lifecycle work, read current MotorLab CORE/governance/routing/registry state and reconcile any relevant active job/checkpoint/lock state.
8. This hook is orchestration metadata only. It must not alter MusicLab application logic, UI, package identity, signing, audio behavior, search behavior, AI behavior or release behavior by itself.
9. If MotorLab control state is unavailable, preserve MusicLab state and report the blocker rather than guessing.
10. Any future MotorLab governance revision in Br174/Chatgpt supersedes frozen assumptions in this hook.
