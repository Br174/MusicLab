MANDATORY RULES
1. First user-visible project line: `⚙️ MotorLab attivo`.
2. Reconcile MOTORLAB_PROJECT_STATE_MUSICLAB_V1.txt against newer live repository/job/artifact evidence before choosing starting point.
3. Preserve MusicLab native playback/search/AI/runtime engines and lifecycle identity.
4. Before every NEW write-capable modification, initial mutation wording is intent only. Perform read-only preparation, show Bruno the pre-change report, then wait for his approval before source/config/lifecycle writes.
5. For approved defect/regression work where Bruno expects APK/ZIP, default order is immediate repair -> risk-appropriate verification -> APK/ZIP -> delivery -> causal/prevention follow-up.
6. Safely deferrable causal work goes into POST_ARTIFACT_ROOT_CAUSE_QUEUE; it remains mandatory and part of the same logical operation.
7. Non-deferrable high-risk causes remain before artifact delivery when necessary to trust/install/use the artifact safely.
8. Artifact progress may reach 100% while overall MotorLab progress remains below 100% until causal closure.
9. After Bruno receives an artifact, preserve its exact ref/checksum while he tests it. Later prevention builds are separate LAB/ref/artifact states.
10. Do not use `✅ Problema risolto` or `💯 Conclusione definitiva` while mandatory causal work remains pending.
11. Approval continuity applies only inside described scope; materially broader post-artifact prevention requires amended report + approval.
12. Apply Change Compatibility Guard, single-writer, Root Cause Closure and lifecycle protections.
13. Technical change history remains provenance/search and distinct from visible restore slots.
14. Visible Registro Modifiche e Ripristini contains only specific Bruno-confirmed working modifications; stable plain integer per feature family.
15. Multi-change LAB/APK work registers only item(s) Bruno explicitly identifies; failed/unconfirmed attempts stay out.
16. `Ripristina N` resolves target read-only, presents restore plan, waits for approval, then uses selective isolated-LAB restore unless whole-version rollback is explicit.
17. Eligible isolated LAB loops use risk-scaled Fast Iteration/No-Spin; HIGH risk and CANDIDATA/MADRE retain full gates.
18. Synchronize newer MotorLab releases only at safe boundaries, preserving LAST_GOOD. Metadata-only sync must not intentionally alter application runtime.
