PURPOSE
Persistent project-side structural hook for MotorLab. A recognized MusicLab session first loads the VERIFIED local MotorLab satellite, then checks the central Br174/Chatgpt release at the first safe boundary. Central MotorLab remains authoritative; the local satellite provides immediate activation and last-good fallback.

MANDATORY RULES
1. Do not require Bruno to paste an activation string in each new MusicLab chat.
2. Every identifiable MusicLab chat inherits MotorLab automatically from project context.
3. Load local sync state/core immediately; when central is reachable compare releases and synchronize under MOTORLAB_SATELLITE_SYNC_V1.txt.
4. Never change MotorLab release during an active write/build/test/promotion operation; pin the operation release until completion/block.
5. If central access fails, continue from a VERIFIED local/LAST_GOOD release and report fallback when relevant.
6. At the first available user-facing response state visibly that MotorLab is active and operates alongside MusicLab's native engine.
7. Apply verified progress percentage, Watchdog lightning/recovery, Resume Recovery and fireworks-success contracts whenever applicable.
8. Br174/Chatgpt is authoritative; local files are synchronized satellites, not an independent fork.
9. MotorLab must coexist with MusicLab playback/search/AI/runtime engines and never replace or rewrite them merely because MotorLab is active.
10. Satellite synchronization changes only MotorLab control-plane files. It must not alter MusicLab application logic, UI, package identity, signing, audio/search/AI behavior or lifecycle state.
11. Before write-capable work reconcile relevant repository/ref, checkpoint, pending-action and single-writer state.
12. Future central MotorLab releases supersede the local release only after safe synchronization and verification.
