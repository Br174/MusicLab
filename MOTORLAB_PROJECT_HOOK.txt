PURPOSE
Persistent MusicLab-side structural hook for MotorLab. Every recognizable MusicLab chat activates MotorLab first, loads the verified local satellite, reconciles central MusicLab continuity against live GitHub state, preserves native MusicLab engines, and continues the latest logical operation without a transfer prompt. r12 enforces risk-scaled iteration/No-Spin; r13 adds semantic historical change lookup and selective exact restore from immutable Git provenance.

MANDATORY RULES
1. MotorLab activates before substantive MusicLab response/tool/write/build work.
2. First user-visible line is "⚙️ MotorLab rNN attivo", where rNN matches the pinned session release.
3. Do not require Bruno to paste activation or transfer prompts.
4. Load MOTORLAB_PROJECT_STATE_MUSICLAB_V1.txt and reconcile against live repo/ref/head/workflow/job/artifact evidence before choosing current starting point.
5. Load MOTORLAB_CHANGE_REGISTRY_MUSICLAB_V1.txt for historical semantic lookup/restoration; it never overrides newer current-state evidence.
6. Live newer evidence wins over stale continuity/older UAB registry/chat memory for current state.
7. Preserve same ACTIVE_OPERATION_ID/progress floor across chat ids while logical task remains same.
8. If unfinished work exists, Resume Recovery + Watchdog continue it before unrelated writes.
9. Refresh central MusicLab continuity at material continuation-relevant transitions when technically possible.
10. Load local sync/core immediately; synchronize central release only at safe boundaries and preserve LAST_GOOD.
11. MotorLab coexists with MusicLab playback/search/AI/runtime engines and never replaces them.
12. Satellite/continuity/history metadata must not alter MusicLab application logic, UI, package identity, signing, audio/search/AI behavior or lifecycle state.
13. Apply Change Compatibility Guard before writes/restores and preserve single-writer/lifecycle safety.
14. Apply MOTORLAB_FAST_ITERATION_NO_SPIN_V1.txt; eligible isolated LAB loops use LOW/MEDIUM/HIGH risk profile while CANDIDATA/MADRE gates remain unchanged.
15. When a persistent executor has accepted work and job id/checkpoint/next-safe-step are recorded, do not keep ordinary chat polling indefinitely; max two unchanged foreground probes by default, then HANDOFF_COMPLETE.
16. For a historical request such as "player", search the semantic MusicLab registry first. Verify selected commit/ref before writing.
17. If several materially different registered matches remain and Bruno has not specified one, show concise date/LAB-labelled choices instead of guessing.
18. Default feature restore creates a new isolated LAB from current proper baseline and replays only the selected registered change while preserving unrelated later work; never direct-edit MADRE.
19. A whole old version is restored only on explicit whole-version intent.
20. If an older MusicLab change predates r13 and is not indexed, perform bounded verified Git/ledger backfill, persist the new record, then use it.
21. Every newly verified Bruno-requested material MusicLab change and every successful restore is automatically written through to the central change registry when possible.
22. UAB remains canonical for installable MusicLab APK/ZIP output; avoid redundant build/test phases that add no distinct verification value.
23. Pollicino remains external MotorLab control-plane infrastructure: never inject liveness/breadcrumb code into MusicLab runtime/source.
24. The external Codex sidecar self-enrolls through D1-gated source proof using the verified stable satellite POLLICINO_PROOF_HEAD first, with current project/active-operation SHA as fallback; it receives only an ephemeral session token and uses it for liveness/progress/terminal seals. Provider-native HMAC remains an optional stronger mode when already available. Never place secrets or session tokens in repository text.
