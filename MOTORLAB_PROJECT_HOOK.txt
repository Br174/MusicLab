PURPOSE
Persistent MusicLab-side structural hook for MotorLab. Every recognizable MusicLab chat activates MotorLab first, loads the verified local satellite, loads/reconciles the central MusicLab project-state ledger against live GitHub state, preserves the MusicLab native/domain engine, and continues the latest logical operation without requiring a transfer prompt. r12 additionally enforces risk-scaled iterative LAB verification and No-Spin durable handoff.

MANDATORY RULES
1. MotorLab activates before substantive MusicLab response/tool/write/build work.
2. First user-visible line is "⚙️ MotorLab attivo".
3. Do not require Bruno to paste activation or transfer prompts.
4. Load MOTORLAB_PROJECT_STATE_MUSICLAB_V1.txt and reconcile it against live repo/ref/head/workflow/job/artifact evidence before choosing a starting point.
5. Live newer evidence wins over stale ledger/older UAB registry/chat memory.
6. Preserve same ACTIVE_OPERATION_ID/progress floor across chat ids while the logical task remains the same.
7. If unfinished work exists, Resume Recovery + Watchdog continue it before unrelated writes.
8. Refresh the central MusicLab ledger at material continuation-relevant transitions and substantial-turn handoff/termination when technically possible.
9. Load local sync state/core immediately; synchronize central release only at safe boundaries and preserve LAST_GOOD.
10. MotorLab coexists with MusicLab playback/search/AI/runtime engines and never replaces them merely because MotorLab is active.
11. Satellite/continuity metadata must not alter MusicLab application logic, UI, package identity, signing, audio/search/AI behavior or lifecycle state.
12. Apply Change Compatibility Guard before writes and preserve single-writer/lifecycle safety.
13. Load/apply MOTORLAB_FAST_ITERATION_NO_SPIN_V1.txt; it coordinates existing owners and must not create a second Watchdog/executor/recovery path.
14. For eligible isolated LAB correction loops, classify LOW/MEDIUM/HIGH risk and use the MusicLab r12 profile. LOW/MEDIUM do not automatically run promotion-grade full regression; HIGH does.
15. `:app:testFossDebugUnitTest :innertube:testDebugUnitTest` is full/high-risk grade by default. Run it for LOW/MEDIUM only when affected-test evidence requires it; CANDIDATA/MADRE gates remain unchanged.
16. When GitHub Actions or another approved persistent executor has accepted the job and run id/checkpoint/next-safe-step are recorded, do not keep the ordinary chat in indefinite polling. At most two consecutive unchanged foreground probes by default, then HANDOFF_COMPLETE while the external job continues.
17. On any later cycle, inspect the recorded run/job id before starting another writer; never duplicate a healthy background build merely because the prior chat looked idle.
18. UAB remains the canonical path for isolated MusicLab installable APK/ZIP output; avoid redundant compile/test/build phases that add no distinct verification value.
